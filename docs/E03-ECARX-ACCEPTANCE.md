# E03 实现与实车验收计划

日期：2026-10-10。状态：**计划，尚未执行本页功能验收**。

设计见 [E03 方案](E03-ECARX-DESIGN.md)。在车辆停稳、驻车状态进行车机操作；不修改驾驶控制、车速、告警或安全显示。

## 1. 记录规范

每次记录源码 commit、固件/API 版本、APK 身份、明确选择的输入/显示/音频策略。
记录步骤、预期、真实结果与错误；未执行标为“未测”，不是“通过”。
本地保留详细证据，导出给公开仓库前隐藏车辆/手机标识和身份凭据。
不自动扫描上传车辆属性，不把配置文件、APK 或原始日志提交到公共分支。

## 2. 部署可行性先验收

| ID | 检查 | 通过条件 |
| --- | --- | --- |
| D01 | 自建 APK 安装、UID/权限 | 实际安装成功且读取实际身份；主题应用提示不充当安装成功证据 |
| D02 | ECARX 媒体/Input/DIM | 分接口记录创建、授权、注册结果和原厂回调，权限拒绝保持可见 |
| D03 | CarPlay 运行认证输入 | 按上游构建说明配置仓库外输入并成功连接手机；普通构建成功不替代 |
| D04 | 无外部桥 | 单 APK 路径不依赖 GD 服务；不在接口失败后安装另一个桥 |
| D05 | 默认状态无副作用 | 核对未暂停原导航、未改变系统音频策略/其他无关设置 |

以上决定设计的实车可部署性；未通过时不把静态实现说明当成支持声明。

## 3. 方控输入和原车独占

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| K01 | 播放/暂停/上一首/下一首逐键短按 | 原始事件/语义回调可追溯；手机正确执行一次 |
| K02 | 保持原播放器开启 | CarPlay 动作时原播放器不同时播放、切歌或抢回媒体源 |
| K03 | SDK + Input 同时观察 | 同一次物理操作至多发送一次；当前主通路可见 |
| K04 | 快速两次短按 | 两次真实操作不被时间去重错误吞掉 |
| K05 | 长按/重复/抬起 | 使用真实序列，配对消费，无重复切歌或遗留按下状态 |
| K06 | OK 键、无导航、正在导航 | 显示请求遵循设置，键值/动作以本车事件为依据 |
| K07 | 主界面、后台、界面重建 | 控制跟随有效 CarPlay 会话；不靠前台窗口才工作 |
| K08 | 断连、换会话、退出 | 旧回调不发送；已占用键按实际厂商机制释放 |
| K09 | 媒体源切换、蓝牙输出/通话 | 不同时控制原车蓝牙音乐与 CarPlay；通话职责不被错误抢占 |
| K10 | 输入注册被拒/没有观察到事件 | 分别显示失败或尚无事件，不自动改为日志模式 |

只显示 sent/ready 标志不满足 K01/K02。日志模式只能证明观察和发送，原车消费需要另一份实际证据。

## 4. 仪表：视频、导航和原厂模式分别验收

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| C01 | 发现目标显示区域 | 名称、ID、逻辑尺寸、权限和地图区域一致；不是任意副屏 |
| C02 | iPhone 提供仪表内容 | 保存脱敏的内容 URL/协议角色；明确所用 iOS 与导航 App |
| C03 | 类型 111、Surface、首帧 | 实际收到视频、完成解码/渲染，区分没有内容、没有帧和输出失败 |
| C04 | DIM 放行与画面可见 | 原厂状态和真实可见地图都有证据，创建窗口不替代 |
| C05 | 转向/距离/道路/ETA | 使用真实导航字段，不把临时激活内容当作路线缓存 |
| C06 | 三指显示/收起与 OK | 事件由哪层收到可见；实际映射一次触发，不双发或残留手机触摸 |
| C07 | 不暂停原导航的长会话 | 导航持续更新、屏源不反复争抢；记录真实固件及观察过程 |
| C08 | 原导航主动开始/后台活动 | 争用结果可重复，模式改变不被误报为应用视频故障 |
| C09 | 收起、手机断连、会话替换 | 撤销本次显示请求、释放窗口/视频、返回原模式，无黑屏/最后一帧滞留 |
| C10 | Activity 重建 | 不误判会话结束，不留下重复窗口，也不由旧回调抢屏 |
| C11 | 副屏消失/厂商服务重连 | 明确状态变化，释放已占用资源；不自行换到其他显示器 |
| C12 | 不提供第二路地图的手机/App | 明确报告内容不支持；不暗中改为主屏截图或 TBT |
| C13 | 安全显示区域 | 车速、告警和原厂固定区域保持可见；地图标记/裁切按 E03 标定 |

视频首帧、原厂模式要求的先后顺序通过 E03 运行证据确定，不照搬 GD 内部未知的进入/恢复实现。
完整地图与 TBT 各有结果；TBT 通过不代表地图通过。

## 5. 可选暂停原导航与恢复

只在用户明确选择争用处理时执行此组；默认策略不改变服务启用状态。

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| R01 | 选项关闭 | 全程没有改变原导航启用状态 |
| R02 | 原状态为 DEFAULT/ENABLED | 修改前同步保存精确原状态与操作归属，确认实际改变 |
| R03 | 原本 DISABLED 等状态 | 保留原状，不记录虚假的“本应用暂停”归属 |
| R04 | 正常收起、断连、关闭选项 | 恢复精确原状态并核对；恢复确认前不清除记录 |
| R05 | 修改被拒/恢复被拒 | 具体 API/权限/返回状态可见，不报告已暂停/已恢复 |
| R06 | 进程强杀、重启、重新启动 App | 下次启动核对持久记录与实际状态；不宣称退出回调必定运行 |
| R07 | 用户/其他程序中途改变状态 | 检测冲突，明确显示，不盲目覆盖新状态 |
| R08 | 重复点击、延迟回调、切换会话 | 状态串行且归属有效，旧任务不重新停用/恢复新会话资源 |

故意执行强杀等异常场景前，先保存恢复入口和原状态；这部分不得在用户不知情时自动触发。

## 6. 独立音量与焦点

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 同时有音乐和导航播报 | 分角色记录真实流、AudioAttributes/stream 和输出路由 |
| A02 | 原车分别调整音乐/导航 | 两套实际音量状态及听感分别变化，改变一类不带动另一类 |
| A03 | 再次播报与重新连接 | 两套用户音量独立保持；不是播报间隙恢复固定 1.0 |
| A04 | 导航自动压低音乐 | 单次压低、结束恢复用户增益，不与 OEM 压低叠加两遍 |
| A05 | 通话/助手介入与结束 | 优先级正确、麦克风路径正确；仅撤销本次占用，不误恢复用户暂停的音乐 |
| A06 | 用户在播报中调节音量/暂停 | 后续恢复不覆盖新选择，音量键职责明确 |
| A07 | 音频服务拒绝路由/用途值 | 原因可见，不静默改用途值或退到统一媒体通道 |
| A08 | 应用内独立增益（若显式实现） | 与系统独立音量分开命名、分开结果，不替 A02 报通过 |
| A09 | 蓝牙、CarPlay 输出切换 | 无双声、无路由归属残留，测试结果记录所选输出方式 |

若系统把两个用途合并为同一音量状态，A02 记失败，而不是以 ducking 的音乐变小充当成功。
其他车型私有 stream 的测试结果不移植成 E03 验收结论。

## 7. 自动化检查的责任

以下测试在实现阶段添加，不是本轮已运行/通过：

- 主通路选择、真实 action 映射、DOWN/UP 配对、快速重复操作、旧会话事件。
- SDK 注册成功但未观察事件、命令入队但无手机结果、消费未确认的状态区分。
- 显示请求/Surface/首帧/DIM 的不同排列，退出与旧回调交错，重复资源释放。
- 精确原状态保存/恢复、状态冲突、失败不清记录；使用明确测试实现注入依赖，不在产品中模拟成功。
- 导航/音乐/通话/助手路由分类，用户增益与压低效果组合，结束不覆盖新选择。
- 设置分类、全语言字符串、重连提示，以及无凭据/原始车辆日志发布检查。

功能改动按根 AGENTS.md 执行完整 test/lint/assemble。自动测试有结果才标通过，实车验收单独记录。
